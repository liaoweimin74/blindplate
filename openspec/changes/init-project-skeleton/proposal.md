## Why

当前工厂盲板管理依赖纸质台账和人工记录，存在以下痛点：

1. **信息滞后** — 盲板安装/拆除状态无法实时同步，导致检修计划依赖人工沟通
2. **查询困难** — 纸质台账难以快速检索特定盲板的位置、规格、历史记录
3. **审批不透明** — 安装/拆除操作缺乏在线审批流程，责任追溯困难
4. **巡检不闭环** — 巡检发现的问题缺乏系统化跟踪，整改容易遗漏

随着工厂智能化管理推进，需要一套电子化盲板管理系统，实现盲板全生命周期的数字化管理，提升设备管理效率和安全合规水平。

## What Changes

**从**: 纸质台账 + 人工沟通 + Excel 统计

**到**: 电子化系统 + 在线审批 + 实时报表

**具体变更：**

1. **盲板信息电子化** — 建立盲板台账数据库，支持规格、材质、位置等信息的结构化管理
2. **操作流程在线化** — 安装/拆除操作通过工单系统流转，支持多级审批
3. **巡检管理规范化** — 巡检计划自动提醒，异常问题闭环跟踪
4. **统计分析自动化** — 盲板使用情况、巡检完成率等指标自动生成报表
5. **权限控制精细化** — 不同角色（管理员/班组长/操作员/巡检员）拥有不同操作权限

## Capabilities

### New Capabilities

- `user-auth`: 用户认证与权限管理，包括登录、JWT Token 管理、角色权限控制
- `blindplate-catalog`: 盲板基础信息管理，包括台账 CRUD、规格参数维护
- `location-tree`: 位置层级管理，包括装置区域、管道系统、盲板位置的树形结构
- `operation-workorder`: 安装/拆除操作工单管理，包括工单创建、审批流程、状态跟踪
- `inspection-plan`: 巡检计划与执行管理，包括计划制定、巡检记录、异常闭环
- `report-dashboard`: 统计报表与数据看板，包括盲板统计、巡检报表、数据可视化

### Modified Capabilities

（无，绿地项目无现有 capability）

## Impact

**代码影响：**
- 新建后端项目 `blindplate-server`，包含 6 个业务模块
- 新建前端项目 `blindplate-web`，包含对应页面和组件
- 新建 MySQL 数据库 `blindplate_db`，包含 10+ 张表

**API 影响：**
- 新增 RESTful API 约 20+ 个端点
- 统一返回格式 `Result<T>`，所有 API 遵循相同规范

**依赖影响：**
- 后端：Spring Boot 3.x、Spring Data JPA、Spring Security、MySQL Connector
- 前端：Vue3、Element Plus、Axios、Pinia、Vue Router

**部署影响：**
- 内网服务器部署，需要 Java 17+、Node.js 18+、MySQL 8.0
- Nginx 反向代理，前端静态资源 + 后端 API 统一入口
