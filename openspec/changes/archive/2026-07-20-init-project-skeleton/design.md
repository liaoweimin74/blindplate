## Context

盲板管理系统是工业管道盲板的全生命周期管理平台。当前项目为绿地项目，无现有代码。系统需支持停车检修管理和日常运维管理两大场景，服务于化工、石油等流程工业企业的设备管理需求。

盲板（Blind Plate）是管道系统中用于隔离的关键安全设备，其安装/拆除状态直接影响生产安全。传统的纸质台账管理方式存在信息滞后、查询困难、审批流程不透明等问题。

**约束条件：**
- 内网部署，无需公网访问
- 独立系统，暂不与其他系统集成
- 团队规模未知，需降低协作复杂度
- 需支持多角色权限控制

## Goals / Non-Goals

**Goals:**
1. 建立盲板电子化台账，替代纸质管理
2. 实现安装/拆除操作的在线审批流程
3. 支持定期巡检和异常闭环管理
4. 提供统计报表辅助决策
5. 预留模块边界，支持未来功能扩展

**Non-Goals:**
1. 不实现移动端 App（Web 端优先）
2. 不实现与 ERP/MES/DCS 的集成（独立系统）
3. 不实现复杂的报表自定义引擎（使用 SQL 直接查询）
4. 不实现多租户支持（单企业使用）
5. 不实现工作流引擎（简单审批状态机即可）

## Decisions

### D1: 模块化单体架构

**选择**: Spring Boot 单体部署，内部按业务模块严格分包

**理由**:
- 内网环境，运维简单是第一优先级
- 需求明确且范围可控，不需要微服务的扩展性
- 模块间通过 Service 接口通信，未来可独立拆分为微服务
- 降低开发和部署复杂度

**替代方案**:
- 微服务架构：扩展性强但复杂度过高，不适合当前阶段
- 纯单体：无模块边界，未来扩展困难

### D2: JWT 无状态认证

**选择**: Spring Security + JWT，Token 有效期 24 小时

**理由**:
- 内网环境，简单够用
- 无状态设计，无需 Session 存储
- 前后端分离架构天然适合 Token 认证

**替代方案**:
- OAuth2：功能强大但复杂度过高，不适合内网简单场景
- Session-based：需要服务端存储，不适合前后端分离

### D3: JPA + MySQL 持久化

**选择**: Spring Data JPA + MySQL 8.0

**理由**:
- JPA 开发效率高，适合 CRUD 密集型应用
- MySQL 在内网环境稳定可靠
- JPA Auditing 自动记录创建/修改时间

**替代方案**:
- MyBatis：更灵活但开发效率低
- PostgreSQL：功能更强但 MySQL 在国内更普及

### D4: 前端 Vue3 + Element Plus

**选择**: Vue3 + TypeScript + Vite + Element Plus

**理由**:
- Vue3 在国内生态成熟，学习曲线平缓
- Element Plus 组件丰富，适合后台管理系统
- TypeScript 提供类型安全
- Vite 构建速度快

**替代方案**:
- React + Ant Design：生态更强但 Vue3 在国内更普及
- Next.js：SSR 对内网管理系统无意义

### D5: 报表通过 SQL 聚合

**选择**: 不建报表表，通过 SQL 聚合查询生成报表

**理由**:
- 报表需求相对简单，不需要复杂的数据仓库
- SQL 聚合灵活，可随时调整统计维度
- 避免数据冗余和同步问题

**替代方案**:
- 建报表表：数据冗余，维护成本高
- 引入报表引擎：过度设计

## Risks / Trade-offs

### R1: 模块边界可能被突破
- **风险**: 开发过程中模块间可能出现直接依赖 Repository 的情况
- **缓解**: 代码审查 + 模块间通过 Service 接口通信的强制约定

### R2: JWT 无法主动失效
- **风险**: 用户修改密码后旧 Token 仍有效（24h 内）
- **缓解**: 内网环境风险可控，可通过黑名单机制后续扩展

### R3: 报表性能可能不足
- **风险**: 数据量大时 SQL 聚合可能变慢
- **缓解**: 为常用查询字段建立索引，必要时引入缓存

### R4: 前端打包体积
- **风险**: Element Plus 全量导入会导致打包体积过大
- **缓解**: 按需导入，Vite 自动 Tree-shaking
