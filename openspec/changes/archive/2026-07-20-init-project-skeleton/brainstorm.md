## Design Summary

盲板管理系统（Blind Plate Management System）— 工业管道盲板的全生命周期管理平台，支持停车检修管理和日常运维管理两大场景。

### 核心模块

1. **盲板信息管理** — 盲板台账、规格参数、材质、尺寸等基础信息 CRUD
2. **位置管理** — 管道系统、装置区域、盲板位置的层级树形管理
3. **安装/拆除管理** — 盲板安装、拆除、复位的操作工单和审批流程
4. **巡检管理** — 定期巡检计划、巡检记录、异常上报与整改跟踪
5. **报表统计** — 盲板使用统计、安全合规报表、数据分析（SQL 聚合）
6. **权限管理** — 多角色（管理员、班组长、操作员、巡检员）+ 菜单权限

### 技术栈

- **后端**: Spring Boot 3.x + Spring Data JPA + MySQL 8.0
- **前端**: Vue3 + TypeScript + Vite + Element Plus
- **认证**: JWT Token（无状态，24h 有效期）
- **部署**: 内网 Nginx 反向代理

## Alternatives Considered

### 方案 A：单体应用
- **做法**: Spring Boot 单体，前端 Vue3 独立部署，Nginx 反向代理统一入口
- **优点**: 开发快、部署简单、适合中小团队、内网环境运维成本低
- **缺点**: 后期模块增多时扩展性一般
- **为何未采���**: 虽然务实，但无法满足未来模块扩展需求

### 方案 B：微服务架构
- **做法**: 按模块拆分为独立微服务（盲板服务、位置服务、巡检服务等），Spring Cloud + Gateway
- **优点**: 模块独立部署、扩展性强
- **缺点**: 运维复杂度高、开发成本高、内网环境收益有限
- **为何未采用**: 当前需求不需要微服务的扩展性，过度设计

### 方案 C：模块化单体（Agreed）
- **做法**: 单体部署但内部按模块严格分包（blindplate/、location/、inspection/），预留微服务拆分接口
- **优点**: 兼顾开发效率和未来扩展性
- **缺点**: 比方案 A 稍复杂，需要额外的模块边界设计
- **为何采用**: 最佳平衡点 — 开发效率高，同时为未来扩展预留空间

## Agreed Approach

采用**方案 C：模块化单体**。理由：

1. 需求明确且范围可控，不需要微服务的复杂度
2. 内网部署环境，运维简单是第一优先级
3. 模块间通过接口通信，未来可独立拆分为微服务
4. 团队规模未知，单体降低协作成本

## Key Decisions

1. **模块化分包而非微服务** — 单体部署，模块间通过 Service 接口通信，禁止直接依赖其他模块的 Repository
2. **JWT 无状态认证** — 内网环境，简单够用，无需 OAuth2 复杂度
3. **JPA Auditing 自动记录** — 创建/修改时间自动填充，减少样板代码
4. **报表通过 SQL 聚合** — 不额外建报表表，保持灵活性
5. **操作工单审批流程** — 待审批→已批准→已完成 / 已驳回，支持完整闭环
6. **巡检异常闭环** — 发现异常→整改→复查，确保问题不遗漏
